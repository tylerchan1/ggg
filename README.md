# RE:EDUCATION

고등학교 「교육의 이해」 수업용 교육정책 시뮬레이션입니다. 교육감이 되어 2026년부터 2036년까지 디지털·AI 소양과 생태전환을 위한 정책을 선택합니다. 정규 선택은 5회, 긴급 위기는 최대 2회입니다. 최종 보고서에 나온 사회 변화를 근거로 후임 교육감에게 인수인계서를 작성합니다. 목표 플레이 시간은 약 3~4분입니다.

## 로컬 실행

저장소 루트에서 정적 파일 서버를 실행하고 브라우저로 접속합니다.

```sh
python3 -m http.server 3000
```

- 학생 화면은 [http://localhost:3000](http://localhost:3000)에서 엽니다.
- 교사 화면은 [http://localhost:3000/?teacher=1](http://localhost:3000/?teacher=1)에서 엽니다.
- 학생은 교사가 생성한 수업 코드와 이름 또는 별칭으로 참여합니다. 접속 링크의 코드는 입력란에 자동으로 채워집니다. 참여 화면과 교육감 역할 안내에서 **게임 시작**을 누른 뒤 첫 사건이 열립니다. 연결에 실패하면 같은 정보로 다시 시도할 수 있습니다.

## Firebase 콘솔에서 직접 설정하기

아래 순서대로 설정합니다. 현재 프로젝트는 `re-edu`이고 웹 앱 설정은 `config.js`에 들어 있습니다.

1. [Firebase 콘솔](https://console.firebase.google.com/)의 **프로젝트 만들기**에서 프로젝트를 생성합니다. Google 애널리틱스는 선택 사항입니다. 이 앱은 Spark 요금제의 Authentication과 Cloud Firestore를 사용하며, Cloud Functions나 결제 정보가 필요하지 않습니다.
2. **빌드 → Authentication → 시작하기 → 로그인 방법**에서 **익명**과 **이메일/비밀번호**를 각각 사용 설정하고 저장합니다. 이메일 링크 옵션은 사용하지 않습니다.
3. **빌드 → Firestore Database → 데이터베이스 만들기**를 선택합니다. 버전 선택이 나오면 **Standard**, 데이터베이스 ID는 **(default)**를 선택합니다. 위치는 수업 환경에 맞게 선택하고 **프로덕션 모드에서 시작**합니다.
4. **Firestore Database → 규칙**에서 [firestore.rules](./firestore.rules) 전체를 붙여넣고 **게시**합니다. 교사는 자신이 만든 수업의 상세 기록만 읽을 수 있습니다. 학생은 자기 상세 기록을 읽을 수 있고, 제출 후 같은 수업의 공개 답변을 읽을 수 있습니다.
5. **Authentication → 사용자 → 사용자 추가**를 눌러 교사 이메일과 비밀번호를 등록합니다. 사용자 목록에서 해당 사용자의 **UID**를 복사합니다. **Firestore Database → 데이터 → 컬렉션 시작**을 눌러 컬렉션 ID를 `teachers`로 지정합니다. 문서 ID에 복사한 UID를 그대로 붙여넣고, 필드 이름 `role`, 유형 `string`, 값 `teacher`를 입력해 저장합니다. 이미 `teachers` 컬렉션이 있으면 **문서 추가**를 사용합니다. 교사 비밀번호는 채팅이나 저장소에 공유할 필요가 없습니다.
6. 다른 Firebase 프로젝트에서 실행하려면 **프로젝트 설정 → 일반 → 내 앱 → 웹 앱(</>)**에서 웹 앱을 등록합니다. Firebase Hosting 체크박스는 비워 두고 **SDK 설정 및 구성**의 `firebaseConfig` 객체를 `config.js`에 넣습니다. 이 객체는 공개 웹 앱 설정입니다. 서비스 계정 키나 교사 비밀번호와 같은 비공개 인증 정보는 저장소에 넣지 않습니다. 설정이 비어 있으면 학생에게 서버 연결 안내가 표시됩니다.

## GitHub Pages 및 실제 연결 확인

저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**와 배포 브랜치의 **/(root)**를 선택합니다. 이미 Pages를 사용 중이라면 기존 배포 브랜치를 유지합니다. 승인된 변경사항이 배포된 HTTPS 주소에서 교사 화면(`?teacher=1`)을 열면 학생 URL과 QR코드에 같은 배포 주소가 사용됩니다.

- 교사 계정으로 로그인해 새 수업을 만든 뒤 참여 코드, URL, QR코드를 확인합니다.
- 별도의 브라우저 또는 휴대폰으로 참여해 별칭을 입력하고 게임을 진행합니다. 참가하면 상단 집계가 바뀌고, 최종 제출하면 새로고침 없이 게시판에 카드가 표시되어야 합니다. 카드에서 사회 보고서, NEWS, 정책 결정 및 긴급 대응 기록을 확인합니다.
- 여러 기기로 동시에 참여하고, 진행 중 새로고침과 **↻ 처음부터**를 확인합니다. 제출을 다시 시도하면 첫 제출이 남아야 합니다. 인터넷을 끊은 상태에서 제출한 뒤 연결을 복구해 **다시 전송하기**도 확인합니다.
- 다른 교사 또는 등록되지 않은 교사 계정으로 첫 교사의 수업에 접근할 수 없는지 확인합니다. 학생의 타인 기록 접근과 제출 불변성은 Firestore Emulator 테스트에서도 확인할 수 있습니다.

### 기존 수업 업데이트

운영에 반영하는 날 [Firestore → 규칙](https://console.firebase.google.com/project/re-edu/firestore/rules)에서 [firestore.rules](./firestore.rules) 전체를 복사해 게시한 뒤 새 버전을 배포합니다. 기존 학생 탭은 새로고침합니다. 규칙 게시와 새 버전 로드 사이에는 이전 클라이언트에서 제출이 거절될 수 있으므로 제출 중인 수업이 없는 시간에 적용합니다. Firebase 인증 방식, 교사 등록 및 데이터베이스 위치는 기존 설정을 사용합니다.

Firestore의 `classes/{code}/students/{uid}`에는 교사용 상세 기록을 보관합니다. `classes/{code}/answers/{uid}`에는 이름, 교육, 이유, 제출 시각만 저장합니다. 새 제출은 한 트랜잭션에서 두 문서에 반영됩니다. 제출한 학생만 자기 수업의 공개 답변을 읽을 수 있고, 공개 답변은 생성 후 수정하거나 삭제할 수 없습니다. 예전 제출은 같은 익명 계정으로 완료 화면을 다시 열 때 공유 게시판에도 올라갑니다.

같은 브라우저에서 **↻ 처음부터**를 누르면 기존 학생으로 다시 플레이합니다. **다른 이름으로 참여**를 누르면 학생 인증과 현재 진행 상태를 초기화하며, 코드가 채워진 참여 화면에서 새 이름으로 참여할 수 있습니다. 이때 새 익명 UID가 생성되고 이전 제출과 교사 로그인은 유지됩니다.

### 사회혼란 적용 시점

사회혼란의 초기값은 75입니다. 정규 정책을 선택하면 미래 사회의 결과를 NEWS로 즉시 보여주고, 팝업이 열릴 때 사회혼란을 한 번 반영합니다. 아래 연도는 기사에 표시하는 미래 시점입니다. 팝업 확인, 새로고침, 최종 보고서에서 기사 다시 읽기는 지표를 바꾸지 않습니다. 업데이트 전에 시작한 수업 플레이는 기존 순서로 이어지고, **↻ 처음부터**로 새로 시작하면 즉시 NEWS 방식이 적용됩니다.

| 기사 속 미래 연도 | 정책 출처 | 거절 결과 | 수락 결과 |
| --- | --- | ---: | ---: |
| 2030년 | EVENT 01 | +5 | +10 |
| 2031년 | EVENT 02 | +10 | −10 |
| 2036년 | EVENT 03-A | +10 | −15 |
| 2036년 | EVENT 03-B | +5 | −10 |
| 2036년 | EVENT 04-A | +5 | −15 |
| 2036년 | EVENT 04-B | +10 | −15 |
| 2036년 | EVENT 05-A/B | −10 | −15 |

긴급 대응 중 학생 지지도 위기(CRISIS 02)에서 추가 수업 시수를 축소하면 +10, 학생 복지 예산을 확대하면 0입니다. 사회혼란 위기(CRISIS 04)의 두 대응은 모두 −20입니다. 예산·교사 지지도 위기의 대응은 사회혼란을 바꾸지 않습니다. 기존 수치를 사용했습니다.

에필로그는 `artwork/`의 주제별 WebP 일러스트 6종을 재사용합니다. 컴퓨팅 사고력, 디지털 리터러시, 생태전환, 기술 혁신, 허위정보 대응, 환경 문제를 담았습니다. 대표 이미지 기준은 약 16:9이며, 성과·과제 썸네일은 같은 이미지를 4:3으로 잘라 표시합니다.

## 코드 구조

| 파일 | 역할 |
| --- | --- |
| `events.js` | 정규 사건 8개, 위기 사건 4개, 정책 효과, 인물, 뉴스, 사업 축소에 따른 대체 기사 |
| `game.js` | 게임 상태 전이, 지표 갱신, 분기, 정책 직후 NEWS, 위기 감지와 최종 보고서 |
| `student.js`, `ui.js`, `styles.css`, `portraits.js` | 학생 화면, 조작, 진행·인수인계서 저장, 기존 카드 스타일 |
| `teacher.js`, `class-results.js` | 수업 관리, 학생별 결과, 분기별 집계 |
| `backend.js`, `config.js`, `firestore.rules`, `firebase.json` | Firebase 인증, 수업 참여, 데이터 접근 권한, 제출과 실시간 갱신 |

정책 효과와 NEWS를 적용한 뒤 현재 사건 연도의 지표로 위기를 판정합니다. 사회혼란 위기는 수치가 100을 초과할 때 발생하며, 여러 조건이 동시에 충족되면 예산, 학생 지지도, 교사 지지도, 사회혼란 순으로 처리합니다. 위기 사건은 NEWS를 확인한 다음에 표시됩니다. 이미 보여준 기사는 원문 그대로 열람할 수 있고, 이후 프로그램 축소의 영향은 최종 성과와 남은 과제에 반영합니다.

## 테스트와 밸런싱

Node.js 24와 Chromium으로 아래 테스트를 실행합니다.

```sh
npm ci
npm test
```

`npm run test:game`은 경로, 지표, 위기 통계를 출력합니다. `npm run test:browser`는 Chromium에서 학생·교사 흐름을 검증합니다. 기본 위치에 Chromium이 없으면 `CHROMIUM_PATH`에 실행 파일 경로를 지정하세요. 브라우저 테스트는 모의 Firebase SDK를 사용합니다. 실제 Firebase 프로젝트에 연결하는 검증은 위 배포 확인 절차로 진행합니다.

Firestore 보안 규칙을 별도로 실행하려면 Java 21을 설치하고 다음 명령을 실행하세요. 공개 Firebase 프로젝트에 쓰기 작업을 하지 않도록 예제 프로젝트 ID를 사용합니다. 기본 테스트는 에뮬레이터가 꺼져 있으면 이 테스트를 건너뜁니다.

```sh
npx firebase-tools@15.37.0 emulators:exec --only firestore --project demo-re-education "npm run test:rules"
```

| 교사 지지도 | −30–55 | −30–50 |

- 정규 선택 32개 중 13개(40.6%)에서 위기를 만났습니다. 긴급 선택까지 모두 전개한 완결 경로 55개 중 36개에 위기가 있었고, 10개에서 위기가 연쇄됐으며, 11개에서 위기가 남았습니다. 14개는 NEWS 직후 사회혼란 위기를 만났습니다.
- 위기 대응 분기 지점 16개 중 예산 8개, 학생 지지도 2개, 교사 지지도 4개, 사회혼란 2개였습니다.
- EVENT 05의 기본 경로 분포는 친환경 기술 연구원 20개(62.5%), 환경단체 대표 12개(37.5%)였습니다. 긴급 선택까지 포함하면 각각 35개와 20개입니다.
- 모두 거절한 경로는 예산 25~45와 사회혼란 75에 도달했고, 모두 수락한 경로는 예산 15와 사회혼란 30에 도달했습니다. 모두 수락한 경우 교사 지지도는 −30~10이었습니다. 우선하는 지표에 따라 장단점이 달라집니다.
- 학생 지지도 위기의 빈도는 낮고, 일부 경로는 교사 지지도가 −30에 도달합니다. 수업 플레이 테스트에서 학생 부담과 교사 부담의 체감을 확인한 뒤 관련 정책의 지지도 변화량을 조정할 수 있습니다. 현재 값은 요청서대로 적용했습니다.
